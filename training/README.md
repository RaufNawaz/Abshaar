# training/

Configs, adapters, and serving assets for the Bulleh Shah expert model
(plan: `docs/15_bulleh_shah_expert_model_implementation_plan.md`, Phases 5–6).

| Path | What it is |
|---|---|
| `axolotl_qwen3_8b.yml` | Path B (cloud QLoRA) config for Qwen3-8B. Verify field names against current Axolotl docs before a paid run. |
| `Modelfile.abshaar-bulleh` | Ollama Modelfile template for serving the fused model (Phase 6). Fill in the FROM path after fusing. |
| `adapters/` | LoRA adapter checkpoints from `scripts/train_lora.sh` (or imported via `scripts/import_trained_adapter.sh`). Gitignored (large); record SHA-256 + eval scores in `EVAL_MATRIX.md` instead. |
| `EVAL_MATRIX.md` | Final base / base+RAG / LoRA / LoRA+RAG comparison (written in Phase 6). |
| `bundle_src/mac/` | Source of the Path C bundle (Apple Silicon / mlx-lm): five stage scripts, an MLX generation script, README. Committed. |
| `bundle_src/windows/` | Source of the Path D bundle (Windows + NVIDIA / PyTorch): five stage scripts, `train_lora_cuda.py`, `merge_adapter.py`, `generate_outputs.py`, README. Committed. |
| `dist/` | Built bundles and their shippable ZIP / base64 copies. Gitignored build artefacts; regenerated by `scripts/export_training_bundle.sh`. |
| `portable_bundle/` | The earlier, single-script Path C bundle. Superseded by `dist/mac/`; harmless if it is still on disk. |
| `pipeline_logs/` | Per-stage logs and a resume marker from `scripts/thermal_aware_pipeline.sh`. Gitignored. |
| `logs/` | Training logs and `train_summary.json` per run, copied off the training machine. **Committed** — `EVAL_MATRIX.md` cites them for every validation curve. |
| `demo_questions.txt` | Six questions used to smoke-test the served model, chosen to hit different failure modes (famous line, citation-dependent fact, conceptual distinction, cross-poem query, uncertain date, and one about 1947 — which a correct system declines). |
| `rag_outputs/` | Answers produced by the demo questions. Gitignored; regenerate with `scripts/rag_pipeline.sh`. |

| `RUN_AUTHORIZED` | Machine-local, gitignored switch. `thermal_aware_pipeline.sh` refuses to run any model step unless this file exists — create it deliberately (`touch training/RUN_AUTHORIZED`) when you want a run to actually start. |

## Serving and evaluating (added 2026-09-25)

Everything below runs on the Air. Nothing here needs the venv rebuild that
older docs describe — that blocker no longer reproduces (`docs/21`).

| Script | What it does |
|---|---|
| `scripts/rag_pipeline.sh` | Seven resumable stages from "adapter on disk" to "a model that answers": build the index, retrieval-only smoke test, grounded answers, the two Ollama baselines, fetch the mlx base weights, and the tuned model's answers. `status` shows progress and runs nothing; `--redo N` forces a stage. Stages that invoke a model require `RUN_AUTHORIZED`. |
| `scripts/build_index_resumable.py` | `abshaar build-index` rebuilds from zero and `rag.py:_collection(create=True)` **deletes the collection first**, so an interrupted run costs the whole ~50 minutes of BGE-M3 encoding. This asks the collection which ids it already holds and does only the rest. It refuses to write `manifest.json` unless the count matches the knowledge base exactly, so a partial index can never present itself as complete. |
| `scripts/serve_tuned.sh` | Serves an adapter through `mlx_lm.server` on :8080 — `run2` (default), `run1`, or `base`. Prints the adapter's SHA-256 so a run record can name what was actually served. |
| `scripts/overnight.sh` | Unattended driver for all four acceptance runs, in the only order 16 GB allows: both Ollama baselines, then qwen3:8b is unloaded before the mlx server loads the 4-bit 8B. Sends one real generation request before committing hours to a run. |
| `scripts/update_eval_matrix.py` | Writes `EVAL_MATRIX.md`'s acceptance rows and PASS/FAIL verdict **from the eval run files**, never by hand. Withholds the verdict until all four runs exist. `--check` exits non-zero on a stale table. |

### Serving the tuned model

```bash
./scripts/serve_tuned.sh run2                      # :8080
./scripts/abshaar.sh ask --model mlx:run2 "..."    # behind retrieval + citation gate
./scripts/abshaar.sh run-eval --model mlx:run2 --rag
```

A model string beginning `mlx:` routes to the mlx server; anything else goes to
Ollama. The text after the prefix is a **run label** for `eval_baseline.md`, not
a model name — which weights load is set by the server's `--model` /
`--adapter-path`, and `ABSHAAR_MLX_ADAPTER` names the adapter on every request
so a run can never silently grade the base model.

### Never serve the tuned model bare

Asked who Bulleh Shah's murshid was *and what the archive cites for it*, run 2
served without retrieval named the right person and then invented both sources,
one of them authored by a man dead since c. 1728, in the archive's own voice.
Retrieval and the citation gate are what make it usable. Full account in
`EVAL_MATRIX.md` §"Run 2 served, without RAG".

## Paths C and D — training on another machine

Full runbook: `docs/18_workstation_training_runbook.md`.
Exact step-by-step for the Mac path, including the acceptance gate that
still has to run here afterwards: `docs/19_mac_training_walkthrough.md`.

Two machines remove this Air's 16 GB / fanless ceiling. Both are shipped as
self-contained bundles — no repo checkout, no private corpus, no admin
rights, one folder that holds venv, model cache, checkpoints and results.

| Path | Machine | Toolchain | Produces |
|---|---|---|---|
| C | Any Apple Silicon Mac (e.g. a Harvard Mac Studio) | mlx-lm | 8B adapter; an Ollama-servable GGUF only from a bf16 base |
| D | Windows + NVIDIA workstation (RTX 6000 class) | PyTorch + peft | 8B adapter **and** a Q4_K_M GGUF |

Prefer D when the workstation is available: merging and quantising an 8B
model needs memory this Air does not have, so it is the only path that ends
with a servable GGUF without a second heavy machine.

1. Build both bundles here:

       ./scripts/export_training_bundle.sh          # or --target mac|windows

   Outputs land in `training/dist/`: the unpacked bundles, a ~240 KB ZIP each,
   and a base64 `.txt` copy of each ZIP. The `.txt` exists because Gmail and
   most corporate filters block `.ps1`/`.cmd`/`.py` attachments *inside
   archives* and reject the whole message; `training/dist/EMAIL_ME.md` has the
   one-line decode command for each platform.

2. On the other machine, read its README, then run one command:
   `.\RUN_ALL.ps1 -Root D:\abshaar-work` (Windows) or
   `./run_all.sh -r ~/abshaar-work` (Mac). Five stages: bootstrap (downloads
   ~20 GB), train, merge/fuse + GGUF, base-vs-tuned generations, pack.

3. **If the machine wipes itself at sign-out** — Rauf's Windows workstation
   does — the final stage is not optional. It writes `<root>/outbox`,
   `SHA256SUMS.txt` and a small ZIP, then prints exactly what to copy off and
   in what order. Every stage is resumable from `<root>/.stages` markers, and
   pointing `-Root` at an external drive keeps the downloads between sessions.

4. Bring back `abshaar_results_small.zip` (adapter + summaries + generations +
   logs) and, when produced, the GGUF. Then here:
   `./scripts/import_trained_adapter.sh /path/to/outbox/adapter/<model-slug>`,
   `ollama create abshaar-bulleh -f Modelfile.abshaar-bulleh`, and continue
   from `docs/17_training_runbook.md` §6 (fuse/serve/eval stays on the machine
   that serves the model).

The bundles carry only `dataset/{train,valid,eval,probes}.jsonl` — gated,
leak-scanned, with counts and SHA-256 in each bundle's `MANIFEST.md`. No
private knowledge base, no witness texts, no reference translations, no git
history. Do not add corpus files to a bundle.

## Background-friendly local runs (Path A, on this Mac)

`scripts/thermal_aware_pipeline.sh` runs docs/17 Phases 2-5 (index build
through LoRA training) at background scheduling priority (`taskpolicy -c
background` + `nice`) so interactive work stays responsive, skips stages
already completed (resumable across interruptions), and pauses instead of
piling on load when `pmset -g therm` reports the CPU already thermally
throttled. It still requires `training/RUN_AUTHORIZED` to exist before it
will touch Ollama/MLX — creating that file is the same explicit
authorization step the runbook already requires, just made a durable
filesystem switch instead of a one-off chat instruction.

    ./scripts/thermal_aware_pipeline.sh status     # no side effects
    touch training/RUN_AUTHORIZED                  # deliberate opt-in
    ./scripts/thermal_aware_pipeline.sh run         # runs in the current shell; backgroundable with `&`

Rules (from the plan):
- No training run before the baseline evals exist in
  `data/processed/training/eval_baseline.md`.
- Acceptance: tuned+RAG ≥ base+RAG on factual scores AND ≥ base on honesty
  traps. A model that hallucinates more than base is rejected.
- Training data comes ONLY from `data/processed/training/mlx/` (gated,
  leak-scanned). Never point a trainer at raw corpus files.
